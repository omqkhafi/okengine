OKEngine runs as a unified, high-performance runtime built on Bun. Rather than requiring separate process managers, message brokers, and sidecars for local development, the engine orchestrates all eight primitives through a single coherent binary.

The internal architecture separates compile-time static contracts from runtime dynamic execution.

<Callout title="Single Binary, Pluggable Drivers">
  In development, OKEngine runs completely self-contained with in-process or embedded drivers. In production, drivers swap to managed cloud infrastructure without altering your flow code.
</Callout>

```text
┌────────────────────────────────────────────────────────┐
│                      OKEngine Core                     │

└────────────────────────────────────────────────────────┘
        │                    │                  │

  Type Validation     Derived Surfaces   Driver Execution
```

## System Layers

The engine is organized into three architectural layers:

| Layer | Responsibility | Components |
| --- | --- | --- |
| **Compiler** | Static analysis, effect extraction, schema validation | TypeScript AST analyzer, Manifest generator |
| **Kernel** | Flow execution, fx dispatch, telemetry ledger, journal | Effect router, wide-event recorder, durable state machine |
| **Drivers** | Protocol-specific I/O adapters across environments | SQLite / Postgres, Memory / Redis, Local / S3 |

## Execution Planes

To enforce strict security and prevent privilege escalation, OKEngine partitions execution into distinct planes:

- **User Plane:** Standard application flows handling public and authenticated customer requests (`fx.auth`).
- **Operator Plane:** Internal administrative operations and Console diagnostic queries (`fx.operator`).
- **Agent Plane:** AI-driven tool invocations mediated through the Model Context Protocol (`:6535`).

## Standard Port Map

OKEngine uses fixed standard ports across environments to guarantee predictable routing and automated tooling integration:

| Port | Service | Role |
| --- | --- | --- |
| **`:6530`** | **Backend API** | Main HTTP server handling user and trigger traffic |
| **`:6533`** | **Developer Console** | Visual dashboard, effect graph, and live traces |
| **`:6535`** | **App MCP** | Model Context Protocol server exposing backend tools to agents |
| **`:6536`** | **Docs MCP** | Semantic documentation search server for coding agents |
