Swarm consumes the same files `oke docker --prod` already writes. Scale replaceable replicas; put durable state in shared drivers — same contract as [Kubernetes](/docs/get-started/kubernetes).

<Callout title="The one rule">
  Deploy with `docker stack deploy`. Docker’s single `HEALTHCHECK` targets `GET /_/ready`
  (`compose.prod.yml`). Shared-driver limits, SIGTERM drain, and Signal/Channel honesty →
  [Kubernetes](/docs/get-started/kubernetes) (unchanged by orchestrator).
</Callout>

## Quick start

<Steps>

<Step>
### Derive the prod compose layers

```bash
oke docker --prod
```

Emits `Dockerfile`, `compose.yml` (`image: oke-<app>:latest` + `build`), role layers, and
`compose.prod.yml` (`HEALTHCHECK` → `/_/ready`, `deploy.*`, `stop_grace_period: 30s`).
CLI prints merge order; `compose.override.yml` is yours (never written by oke).

</Step>

<Step>
### Build the app image, init Swarm, deploy

`docker stack deploy` ignores `build` — tag first (name matches `compose.yml`):

```bash
docker build -t oke-<app>:latest -f docker/Dockerfile .
docker swarm init
cd docker
docker stack deploy -c compose.yml -c compose.store.sql.yml -c compose.store.kv.yml \
  -c compose.pgdog.yml -c compose.prod.yml myapp
```

Pass every `-c` file the CLI listed (roles follow `images`). Create `secrets:` names via
`docker secret create`, or drop those keys in `compose.override.yml` while using `.env.docker`.

</Step>

<Step>
### Scale and roll

```bash
docker service scale myapp_app=3
docker service update --image oke-<app>:latest myapp_app
```

Prod overlay: `update_config` (`parallelism: 1`, `order: start-first`,
`failure_action: rollback`) and `restart_policy.condition: on-failure`.
Tweak in `compose.override.yml`.

</Step>

</Steps>

## HEALTHCHECK (not two probes)

Swarm has one Docker `HEALTHCHECK` — no separate readiness/liveness.

| Endpoint       | Role in OKE                                            | Swarm                                                                                |
| -------------- | ------------------------------------------------------ | ------------------------------------------------------------------------------------ |
| `GET /_/ready` | Kernel readiness (`booting` → `orphan_scan` → `ready`) | **Use this** — mesh + rolling updates wait; `start_period: 60s` covers orphan resume |
| `GET /health`  | App liveness (create-oke)                              | External monitors only — not a second native probe                                   |

**Consequence:** orphan scan delays “healthy” (and traffic) on purpose. After `start_period`,
failing `/_/ready` can mark the task unhealthy and hit `restart_policy` — Swarm cannot drain
traffic without also counting toward restart.

## TLS at the edge

Swarm's routing mesh reaches tasks; it does not issue certificates.
For HTTPS on the same files, opt in to `images.proxy` (Caddy or Traefik) —
see [Docker · Which proxy?](/docs/get-started/docker#which-proxy).

## Shared guarantees → Kubernetes page

Do not re-derive these here:

- Shared Postgres (optionally via PgDog), Redis, S3 — [Kubernetes · Share backing services](/docs/get-started/kubernetes#share-backing-services)
- `installGracefulShutdown` on SIGTERM — Swarm sends SIGTERM on update/scale the same way; `stop_grace_period: 30s` peers `terminationGracePeriodSeconds` — [Graceful shutdown](/docs/get-started/kubernetes#graceful-shutdown)
- Process-local Signal consume / Channel suppression — [Known multi-instance limits](/docs/get-started/kubernetes#known-multi-instance-limits)

## Troubleshooting

<Accordions>
<Accordion title="Stack deploy ignores my Dockerfile build">

Build and tag first (`docker build -t oke-<app>:latest …`). Swarm runs the `image:` tag only —
never compose `build:`.

</Accordion>
<Accordion title="New replica gets traffic before orphan scan finishes">

Confirm `compose.prod.yml` is in the `-c` list and the task health-checks `/_/ready`.
Without that HEALTHCHECK, Swarm treats “container started” as ready.

</Accordion>
<Accordion title="Multi-node workers cannot reach store-sql">

Generated `networks.oke.driver` is `bridge` (fine for single-node `swarm init`).
Multi-node: set `driver: overlay` in `compose.override.yml`.

</Accordion>
</Accordions>
