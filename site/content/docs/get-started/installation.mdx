This page gets you from zero to a running app on Bun. The engine targets
**Bun ≥ 1.4.0** — prefer it for install, scaffold, and `oke dev`.

<Callout title="The one rule">
  The npm package is `okengine`; the CLI binary is `oke`. Use `bun add` in a project or `bun install
  -g okengine` for a global `oke` on PATH. JSR is the library API only.
</Callout>

## Quick start

<Steps>

<Step>
### Prerequisites

- [Bun](https://bun.sh) ≥ 1.4.0 (`bun --version`)
- [Docker](https://docs.docker.com/get-docker/) with a running daemon (`docker info`)
- A terminal and a code editor

`oke dev` always starts Docker Compose for Postgres / Redis / S3 / SMTP (and other pinned images). Use `oke test` for PGLite tests without Compose.

</Step>

<Step>
### Install the package

Project dependency (framework + local `oke`):

```bash title="Terminal"
bun add okengine
```

Global CLI (`oke` on PATH):

```bash title="Terminal"
bun install -g okengine
```

Library-only via JSR:

```bash title="Terminal"
bunx jsr add @omqkhafi/okengine
```

</Step>

<Step>
### Scaffold with create-oke

```bash title="Terminal"
bunx create-oke@latest my-app
bunx create-oke@latest my-app --template standard
bunx create-oke@latest my-app --template advanced
bunx create-oke@latest my-app --sql postgres
bunx create-oke@latest my-app --yes
```

Two Notes starters: **standard** and **advanced** (adds `store.index` + optional AI).
Both are Docker-first; `test` uses PGLite / memory.

The okengine repo also ships `examples/keel` — a work-management app, not a template.
Run it with `bun run dev:keel` against Compose (Postgres, PgDog, Redis, RustFS, Mailpit,
Meilisearch, llama.cpp). Wipe with `bun run dev:keel:reset`.

On a TTY: pick a template, then **recommended defaults**, **customize**, or
**reuse** (`~/.oke/create-defaults.json`). Reuse applies saved locales / PgDog /
proxy without re-asking; recommended and customize ask and persist those answers.

Customize walks Docker-first facets (including `store.index` with `none`), then
**AI setup** (Recommended / Customize / Off). Project name rejects a non-empty
existing path.

Non-TTY / `--yes` stay scriptable. `--sql postgres` pins SQL; `--ai` runs the
model wizard before install.

</Step>

<Step>
### Run and verify

```bash title="Terminal"
cd my-app
oke dev
```

Four ports come up together (mnemonic: **O·K·E = 6·5·3**):

<Surfaces />

Open `http://localhost:6533`. Paste the **claim code** from the `oke dev` board
(or `oke console claim-code`). Password: **≥ 12** with upper, lower, number, and
special, or **Generate** (copies it).

Flows listed means the install worked — **derived, not configured.**
`bun run web` starts the Vite Notes UI (proxies Flows to the app).

</Step>

</Steps>

## Database sync in `oke dev`

`oke dev` watches schema paths and auto-runs `oke db push` so the database
stays in sync. Opt out with `oke dev --no-db-push` or
`db: { autoPush: false }` in `oke.config.ts`.

A broken `schema.decl.ts` prints a red ● `schema.decl.ts has an error — …` and
keeps the session up — never a quiet `skipped`. Missing `oke.config.ts` / images
still soft-skip.

For production, generate and apply migrations deliberately — never automatic on
boot:

```bash title="Terminal"
oke db generate   # write drizzle/*.sql
oke db migrate    # apply
```

## Docker Compose under `oke dev`

`oke dev` always brings up Compose under `docker/` and runs the app on host Bun
with the `dev` driver profile (filled from `prod` when omitted). Credentials and
host ports are unique per project.

```bash title="Terminal"
oke dev                      # full Compose set from images
oke dev -d store.sql,signal  # optional: only these roles
oke test                     # PGLite tests — no Compose
```

| Protocol            | Env shape (generated)                                                                                           |
| ------------------- | --------------------------------------------------------------------------------------------------------------- |
| Postgres            | `DATABASE_URL` plus `OKE_STORE_SQL_*`                                                                           |
| Redis               | `REDIS_URL` plus `OKE_STORE_KV_PASSWORD`                                                                        |
| S3-compatible files | `S3_ENDPOINT`, `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY`, `S3_BUCKET`, `S3_URL`, `S3_REGION`, `S3_CONSOLE_URL` |
| SMTP email          | `SMTP_URL`, `SMTP_HOST`, `SMTP_PORT`, `MAILPIT_UI_URL`, optional `SMTP_USER` / `SMTP_PASSWORD`                  |

Uncommented supported controls in the generated compose env are preserved when
`oke dev` regenerates the file.

Migrating from `local` / `docker` maps or `oke mode`?
Rename the env keys in `oke.config.ts` to `dev` / `test` / `prod`.

## Troubleshooting

<Accordions>

<Accordion title="oke: command not found after install">
  Install the npm package `okengine` (not JSR alone): `bun add okengine` in the project, or `bun
  install -g okengine` for a global binary. Or invoke via `bunx oke dev`. There is no separate `oke`
  package name — only `okengine`.
</Accordion>

<Accordion title="Docker daemon not running">
  `oke dev` requires Docker. Start Docker Desktop (or your engine), confirm with `docker info`, then
  retry. For tests without Compose, use `oke test`.
</Accordion>

<Accordion title="Console is empty / no flows listed">
  Confirm `oke dev` is running and you opened `:6533`, not `:6530`. Flows appear only after the app
  boots and the Manifest is extracted — fix TypeScript errors in the terminal first.
</Accordion>

<Accordion title="Create first operator fails (password / claim code)">
  Password: ≥ 12 with upper, lower, number, and special — or **Generate**. Copy the claim code from
  the `oke dev` board (30 min TTL) or `oke console claim-code`. The form never gets the code over
  HTTP; the log shows the reason, not a bare `500`.
</Accordion>

<Accordion title="Database out of sync after editing schema">
  `oke dev` auto-pushes by default. If you passed `--no-db-push` or set `db.autoPush: false`, run
  `oke db push` yourself, or re-enable auto-push.
</Accordion>

<Accordion title="Docker containers left after deleting a project">
  Each project gets its own `oke-dev-<id>` compose project; `oke dev` stop keeps volumes. Run
  `oke docker clean` (TTY picker) or `oke docker clean --all --yes` from anywhere to remove
  leftover containers, networks, and volumes.
</Accordion>

<Accordion title="Want a clean keel stack?">
  Stop `bun run dev:keel`, then `bun run dev:keel:reset`. That wipes Compose, `.oke/`, and writes
  `.env.local` from `.env.example`. Next `dev:keel` regenerates stack keys; seed copies them into
  the built-in vault.
</Accordion>

</Accordions>
