This page gets you from zero to a running app on Bun. The engine targets
**Bun ≥ 1.3.14** — prefer it for install, scaffold, and `oke dev`.

<Callout title="The one rule">
  The npm package is `okengine`; the CLI binary is `oke`. Use `bun add` in a project or `bun install
  -g okengine` for a global `oke` on PATH. JSR is the library API only.
</Callout>

## Quick start

<Steps>

<Step>
### Prerequisites

- [Bun](https://bun.sh) ≥ 1.3.14 (`bun --version`)
- A terminal and a code editor

</Step>

<Step>
### Install the package

Project dependency (framework + local `oke`):

```bash title="Terminal"
bun add okengine
```

Global CLI (`oke` on PATH):

```bash title="Terminal"
bun install -g okengine
```

Library-only via JSR:

```bash title="Terminal"
bunx jsr add @omqkhafi/okengine
```

</Step>

<Step>
### Scaffold with create-oke

```bash title="Terminal"
bunx create-oke@latest my-app
bunx create-oke@latest my-app --template standard
bunx create-oke@latest my-app --template advanced
bunx create-oke@latest my-app --sql postgres
bunx create-oke@latest my-app --yes
```

Two Notes starters: **standard** (local-first) and **advanced** (docker-ready +
files/digest/AI).

On a TTY: pick a template, then **recommended defaults**, **customize** (local
or docker first; saved to `~/.oke/create-defaults.json`), or **reuse** matching
saved settings. Project name rejects a non-empty existing path.

Non-TTY / `--yes` stay scriptable. Defaults: local SQLite · Docker/prod Postgres.
`--sql postgres` pins SQL; `--ai` runs the model wizard before install.

Scaffold writes `.oke/mode` (standard → `local`, advanced → `docker`) so the
first `oke dev` skips the mode prompt unless you delete it or pass `--local` /
`--docker`.

</Step>

<Step>
### Run and verify

```bash title="Terminal"
cd my-app
oke dev
```

Four ports come up together (mnemonic: **O·K·E = 6·5·3**):

<Surfaces />

Open `http://localhost:6533`. Claim the Console with the **claim code** printed
once in the `oke dev` log, then create the first operator.

Password policy matches Gate auth: **≥ 12 characters, with a letter and a
number.** If the Console lists your flows, the install worked — **derived, not
configured.**

</Step>

</Steps>

## Local database sync

Local mode watches schema paths and auto-runs `oke db push` so the database
stays in sync. Opt out with `oke dev --no-db-push` or
`db: { autoPush: false }` in `oke.config.ts`.

For production, generate and apply migrations deliberately — never automatic on
boot:

```bash title="Terminal"
oke db generate   # write drizzle/*.sql
oke db migrate    # apply
```

## Docker mode

Want Postgres/Redis like production while the app stays on host Bun?

<DevModes />

```bash title="Terminal"
oke dev --docker   # or: oke dev -d
# or set the saved default: oke mode docker
```

Uses the `docker` driver profile in `oke.config.ts` (filled from `prod` when
omitted). Compose and credentials land under `docker/` (`.env.docker` beside
compose); host ports are unique per project.

Bare `oke dev` uses `.oke/mode` when present (seeded by create-oke). On a TTY
with no saved mode it prompts once and writes the file; non-TTY defaults to
`local`.

| Protocol            | Env shape (generated)                                                                                           |
| ------------------- | --------------------------------------------------------------------------------------------------------------- |
| Postgres            | `DATABASE_URL` plus `OKE_STORE_SQL_*`                                                                           |
| Redis               | `REDIS_URL` plus `OKE_STORE_KV_PASSWORD`                                                                        |
| S3-compatible files | `S3_ENDPOINT`, `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY`, `S3_BUCKET`, `S3_URL`, `S3_REGION`, `S3_CONSOLE_URL` |
| SMTP email          | `SMTP_URL`, `SMTP_HOST`, `SMTP_PORT`, `MAILPIT_UI_URL`, optional `SMTP_USER` / `SMTP_PASSWORD`                  |

Each section also includes commented controls (Redis memory policy, Postgres
init options, Bun S3 session tokens, Mailpit limits). Uncommented supported
controls are preserved when `oke dev --docker` regenerates the file.

## Troubleshooting

<Accordions>

<Accordion title="oke: command not found after install">
  Install the npm package `okengine` (not JSR alone): `bun add okengine` in the project, or `bun
  install -g okengine` for a global binary. Or invoke via `bunx oke dev`. There is no separate `oke`
  package name — only `okengine`.
</Accordion>

<Accordion title="Console is empty / no flows listed">
  Confirm `oke dev` is running and you opened `:6533`, not `:6530`. Flows appear only after the app
  boots and the Manifest is extracted — fix TypeScript errors in the terminal first.
</Accordion>

<Accordion title="Create first operator fails (password / claim code)">
  Use a password with at least 12 characters, including a letter and a number. Copy the claim code
  from the current `oke dev` boot log (it expires in 30 minutes; restart mint a new one). The form
  and the request log now show the reason — not a bare `TransportError` / `500`.
</Accordion>

<Accordion title="Database out of sync after editing schema">
  Local `oke dev` auto-pushes by default. If you passed `--no-db-push` or set `db.autoPush: false`,
  run `oke db push` yourself, or re-enable auto-push.
</Accordion>

<Accordion title="Docker containers left after deleting a project">
  Each project gets its own `oke-dev-<id>` compose stack; `oke dev` stop keeps volumes. Run
  `oke docker clean` (TTY picker) or `oke docker clean --all --yes` from anywhere to remove
  leftover containers, networks, and volumes.
</Accordion>

</Accordions>
