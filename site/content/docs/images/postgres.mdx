Postgres is the default `store.sql` image in docker and prod. `oke docker` matches any image
whose reference contains `postgres`, `pgvector`, or `timescale`, and derives the compose service
for you — no recipe code to write for the common case.

<Callout title="The one rule">
  The driver id stays `postgres` no matter which Postgres-wire image you pin — vendor choice lives
  in `images["store.sql"]`, not in `drivers.store.sql`.
</Callout>

## Pin it

```typescript title="oke.config.ts"
images: {
  "store.sql": "postgres:16-alpine", // any Postgres / pgvector / Timescale image
},
```

## What the recipe configures

| Field          | Value                                                                                                        |
| -------------- | ------------------------------------------------------------------------------------------------------------ |
| Container port | `5432`                                                                                                       |
| Environment    | `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB` — credential refs, never literal secrets in compose YAML |
| Healthcheck    | `pg_isready -U $POSTGRES_USER`, every 5s, 10 retries                                                         |
| Connection URL | `postgres://user:pass@host:5432/db`                                                                          |

`DATABASE_URL` is what the app actually reads (`OKE_STORE_SQL_URL` also works). When PgDog is in
the stack, `DATABASE_URL` points at the pooler instead — see [PgDog](/docs/images/pgdog).
