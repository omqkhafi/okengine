Ollama serves local models over HTTP on port `11434`. Pin `images.ai` and set
`drivers.ai` to `ollama` where you want local inference — there is **no** production
default for AI; prod must declare a driver.

<Callout title="The one rule">
  Name the model (`OKE_AI_MODEL` or `oke ai setup`). On `oke dev -d`, OKE POSTs `/api/pull` to
  **this container's** exposed URL — never a host `ollama` CLI.
</Callout>

## Quick start

<Steps>

<Step>
### Pin driver + image

```typescript title="oke.config.ts"
drivers: {
  ai: { local: "ollama", docker: "ollama", test: "mock" }, // prod: set deliberately
},
images: {
  ai: "ollama/ollama:latest",
},
```

Or run `oke ai setup --provider ollama --yes` to wire driver, env, and `src/ai.ts`.

</Step>

<Step>
### Env written by the stack

```bash title="docker/.env.docker"
OKE_AI_URL=http://127.0.0.1:11434
OKE_AI_MODEL=qwen3.5:9b
```

Container sets `OLLAMA_HOST=0.0.0.0:11434` so the API listens on all interfaces.

</Step>

<Step>
### Boot pulls against the container API

After compose is healthy, `oke dev -d` calls `POST {OKE_AI_URL}/api/pull` with
`${OKE_AI_MODEL:-qwen3.5:9b}` (`stream: false`). That hits the **mapped host port**
of this recipe — not whatever else might listen on `:11434`.

</Step>

</Steps>

<Callout type="warn" title="Host `ollama` CLI is unrelated">
  A host `ollama pull` / `ollama run` often talks to a separately installed daemon on the default
  port — models land **outside** this container. Trust boot `POST /api/pull` against `OKE_AI_URL`
  (or curl that URL yourself).
</Callout>

## Required env

| Variable                                     | Required?         | Meaning                                                            |
| -------------------------------------------- | ----------------- | ------------------------------------------------------------------ |
| `OKE_AI_URL`                                 | **Yes** in docker | Base URL — `oke boot: ollama driver needs OKE_AI_URL` when missing |
| `OKE_AI_MODEL`                               | Recommended       | Model tag to pull/serve (default `qwen3.5:9b`)                     |
| `OLLAMA_HOST`                                | Set by recipe     | `0.0.0.0:11434` inside the container                               |
| `OKE_AI_VISION_MODEL` / `OKE_AI_EMBED_MODEL` | Optional          | Written by `oke ai setup` for logical models                       |

On Apple Silicon hosts running Ollama **outside** Docker, `qwen3.5:9b-mlx` is a
common override — set `OKE_AI_MODEL` accordingly (that path is not this recipe).

## Data and backup

| Volume    | Path            | What it stores                         |
| --------- | --------------- | -------------------------------------- |
| `ai-data` | `/root/.ollama` | Pulled model weights + Ollama metadata |

**Backup means:** preserve `ai-data` so you do not re-download multi-GB models after
every recreate. Deleting the volume forces another full `/api/pull` on next boot
(slow, bandwidth-heavy). Keep `OKE_AI_MODEL` in env — choice is not volume-only.

## Production note

Local Ollama is for docker/dev (and air-gapped prod you deliberately choose). Cloud AI
drivers (`anthropic`, `openai-compatible`, `bedrock`, `vertex`) stay separate.

PII egress rules treat `ollama` as local (no third-party egress) — see
[AI · PII](/docs/elements/ai).

Cold pulls can take minutes; the boot step waits on `/api/pull` before the app
continues. GPU passthrough is **not** configured — CPU inference is the default
compose shape.

## What the recipe configures

| Field          | Value                                                |
| -------------- | ---------------------------------------------------- |
| Container port | `11434`                                              |
| Entrypoint     | Image default (`ollama serve`)                       |
| Healthcheck    | `ollama list`, every 5s, 24 retries, 10s start       |
| Connection URL | `http://host:11434`                                  |
| Model pull     | Host-side `POST /api/pull` to that URL after healthy |

## Troubleshooting

<Accordions>
<Accordion title="oke boot: ollama driver needs OKE_AI_URL">

Docker mode expects `OKE_AI_URL` from `docker/.env.docker` when `images.ai` is pinned.
Locally the default is `http://127.0.0.1:11434`. Prefer `oke ai setup` to wire everything
in one pass.

</Accordion>
<Accordion title="Model missing / I already ran ollama pull on the host">

The host CLI likely filled a **different** Ollama. Check `GET $OKE_AI_URL/api/tags`,
then recreate with `oke dev -d` or `curl -X POST "$OKE_AI_URL/api/pull" -d '{"model":"…","stream":false}'`.
`OllamaUnavailableError` wraps HTTP errors from `/api/chat` and `/api/tags`.

</Accordion>
</Accordions>
