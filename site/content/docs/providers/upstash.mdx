Upstash publishes **two** ways to reach the same database: a standard Redis-protocol TCP endpoint
(port 6379, works with any Redis client unmodified) and a separate HTTP/REST API built for
edge runtimes where raw TCP isn't available.

<Callout title="The one rule">
  oke's `redis` driver speaks the wire protocol — use Upstash's **TCP endpoint** and a `rediss://`
  URL, not the REST API. The REST API is a different transport with its own client library and isn't
  what `fx.store` calls.
</Callout>

## Connect

```bash title="docker/.env.docker or your process env"
REDIS_URL=rediss://default:password@usw1-example-12345.upstash.io:6379
```

The database's dashboard shows both a `redis://` connection string (for TCP clients) and a
separate `UPSTASH_REDIS_REST_URL` / `UPSTASH_REDIS_REST_TOKEN` pair (for the REST API) — only the
first one applies here.

## Feature highlights

| Feature      | Notes                                                                                 |
| ------------ | ------------------------------------------------------------------------------------- |
| TCP endpoint | Standard RESP over TLS, port `6379` — ioredis / node-redis / redis-py work unmodified |
| REST API     | A separate HTTP transport for edge runtimes without TCP — not used by oke's driver    |
| Pricing      | Per-request pricing model rather than a fixed instance size                           |
