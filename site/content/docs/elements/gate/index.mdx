Gate is how your backend **decides whether a caller has permission to act**. In other frameworks, security is an afterthought spread across Express middlewares, Passport strategies, rate-limiter libraries, and ad-hoc tenant decorators. In OKE, Gate provides an explicit security posture.

<Callout title="The one rule">
  **First denial wins**. When multiple gates protect a Flow, they evaluate left-to-right. The first gate to reject the caller terminates execution immediately without evaluating subsequent gates or entering the flow body.
</Callout>

## What is Gate?

Gate spans four unified protection surfaces:

1. **Authentication (`gate.auth`)**: Session validation, JWT verification, and API key resolution.
2. **Multi-Tenancy (`gate.auth.tenant`)**: Automatic tenant isolation injected into `fx.tenant`.
3. **Authorization Policies (`gate.policy`, `gate.scope`)**: Role-based (RBAC) and Attribute-based (ABAC) permission checks.
4. **Rate Limiting (`gate.rate`)**: High-performance sliding-window and token-bucket throttling backed by KV.

```typescript title="src/gates/roles.ts"
import { gate } from "okengine";

export const requireAdmin = gate.policy("adminOnly", async (ctx) => {
  return ctx.user?.role === "admin";
});

export const apiRateLimit = gate.rate("apiThrottling", {
  strategy: "sliding-window-counter",
  limit: 100,
  window: "1m",
});
```

## Attaching Gates to Flows

Gates attach directly to any Flow definition:

```typescript
export const deleteUser = on(
  http.delete("/users/:id"),
  flow("users.delete", {
    gates: [gate.auth, requireAdmin, apiRateLimit],
    do: async ({ id }, fx) => {
      // Guaranteed: user is authenticated, has admin role, and caller is within rate limits
      await fx.store(db).delete(users).where(eq(users.id, id));
    },
  }),
);
```
