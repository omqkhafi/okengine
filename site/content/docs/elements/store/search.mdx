Built-in hybrid search lives on ordinary `store.schema.table()` columns via `.searchable()` and `.embed()`. It runs on PostgreSQL 15+ with plain SQL (GIN + B-tree) — **zero required extensions**. The separate `store.index` facet (Meilisearch / pgvector) remains for genuinely external engines.

## One rule

`.searchable()` is free, synchronous BM25 math. `.embed()` is a separate chain that starts an **async, costed** AI pipeline — never a boolean flag next to `weight`.

## Quick start

<Steps>

<Step>
### Declare searchable columns

```typescript title="src/db/schema.decl.ts"
import { field, store, ai, oke } from "okengine";

const embedder = ai.model("embedder", { provider: "ollama", model: "nomic-embed-text" });
const captionEmbedder = ai.model("caption-embedder", {
  provider: "ollama",
  model: "nomic-embed-text",
});

oke({
  store: {
    search: {
      embed: { model: embedder, dims: 768 },
    },
  },
});

export const articles = store.schema.table("articles", {
  id: field.text().primaryKey(),
  title: field.text().searchable({ weight: 2 }).notNull(),
  body: field.text().searchable().embed(), // inherits model + dims
  caption: field.text().searchable().embed({ model: captionEmbedder }), // override model; dims from default
});
```

Set the project default once under `oke({ store: { search: { embed } } })`. Bare `.embed()` inherits; per-field `{ model?, dims? }` overrides. Bare `.searchable()` still needs **no** `ai` element. `.embed()` without a resolvable model/dims (and without AI) fails loud (`SearchConfigError`).

</Step>

<Step>
### Query with `fx.store(db).search`

```typescript title="src/flows/articles/search.ts"
import { flow } from "okengine";
import { z } from "zod";
import { articles, db } from "../../db/schema.ts";

export const searchArticles = flow("articles.search", {
  in: z.object({ q: z.string() }),
  do: async ({ q }, fx) => {
    const { data, meta } = await fx.store(db).search(articles, {
      query: q,
      // optional: fuse: { strategy: "rrf" }  // default RRF k=60 (Cormack et al. 2009)
      // optional: fuse: { strategy: "weighted", weights: { bm25: 0.4, vector: 0.6 } }
      // optional: rerank: { model: "search.rerank" }  // default false — never silent ask
      limit: 20,
    });
    return { data, meta };
  },
});
```

</Step>

</Steps>

## `?search=` / `?q=` vs hybrid `query` (do not confuse)

These are **two different surfaces** that share English words. Mixing them up has caused real confusion elsewhere in this project — treat them as unrelated.

| Surface | Where | Parameter | Meaning |
| -------- | ----- | --------- | ------- |
| List / live grammar | `parseListQuery` · resource lists · `liveQuery` | `?search=` or `?q=` | Substring `LIKE %term%` across whitelisted columns (default scope `"none"`) |
| Hybrid search | `fx.store(db).search(table, { query })` | `query` | BM25 (± LSH) relevance ranking |

Side by side:

```typescript
// 1) List grammar — substring filter (NOT BM25)
// GET /articles?search=refund&status=eq.active
await liveQuery(fx, articles, input, {
  search: [articles.title], // enables ?search= / ?q= LIKE
  filter: [articles.status],
});

// 2) Hybrid search — BM25 / LSH relevance (NOT LIKE)
await fx.store(db).search(articles, {
  query: "refund policy", // relevance string
  // ...same PostgREST filters / limit / cursor via parseListQuery:
  filterInput: { status: "eq.active", limit: "20" },
});
```

`search()` reuses `parseListQuery` for ordinary column filters, limit, and cursor pagination. Only `query`, `fuse`, and `rerank` are search-specific.

## Async embedding (eventual consistency)

Writes from your app flow **never** call `fx.embed`. A system-owned durable CDC flow (`_oke_search_embed_<table>`) embeds after commit via the Realtime CDC bridge + Journal `fx.step`. A just-written row may be missing from semantic results for a short interval — that window is intentional and documented.

## Backfill

`oke db push` applies shadow columns / indexes but **never** silently backfills a large table. Run deliberately:

```bash
oke db search-backfill <table> [--batch=32]
```

Resumable via Journal durable steps; embed batches pause for provider rate limits.

## Fusion defaults

- **Default:** Reciprocal Rank Fusion with **k = 60** (Cormack, Clarke, Büttcher — SIGIR 2009; MAP flat for k ∈ [20, 100]). Override with `fuse.k`.
- **Opt-in:** `fuse: { strategy: "weighted", weights: { bm25, vector } }` — tuned weighted fusion can outperform RRF on some benchmarks; RRF is the robust default, not unconditionally superior.

## External engines

`store.index` + Meilisearch / pgvector remain available for external engines. They are **not** this capability.
